# Motion Review 动画审查设计草案

状态：设计过程与原型记录，尚未进入实现。日期：2026-09-08。

整合需求与验收以 [PRD V2.0](UI_Review_PRD_V2.0.md) 为准；本文保留设计思路、原型链接与限制说明。

本文在现有截图审查、自动保存、只读 MCP 与文件导出基础上，定义动画审查的首版体验。现有 V1 设计决策仍然有效；本文中的新增交互与接口均为提案。

## 1. 产品目标与默认场景

让用户把录屏中的动画问题，连同时间、画面区域和修改期望交给 Coding Agent。

默认从“只有当前实现录屏”开始，有参考视频时再进入对比。此优先级是本草案采用的设计假设，仍可根据实际使用习惯调整。

核心流程：

> 导入录屏 → 找到问题 → 选择时间 → 可选框选 → 写一句话 → 交给 Agent

图片或视频表达位置，时间表达问题发生的阶段，评论表达修改要求。工具不推断代码位置，不自动决定动画参数，也不修改项目代码。

## 2. 工作区与入口

延续现有三栏：左侧素材列表、中间画布、右侧问题面板。视频播放控制和时间轴位于中间画布下方。

```text
Review 名称                                      导入   交给 Agent
┌──────────────┬──────────────────────────────┬──────────────────┐
│ 素材         │ 弹窗展开          添加参考视频 │ 问题             │
│              │                              │                  │
│ 图片 设置页  │        当前实现录屏           │ #1 展开后突然停止 │
│ 视频 弹窗展开│                              │ 120–420 ms       │
│ 视频 返回转场│                              │                  │
│              │                              │ 问题描述         │
│              ├──────────────────────────────┤ [多行文字输入]   │
│              │ 上一帧 播放 下一帧  0.5×     │                  │
│              │ 0 ms ──[选中时间段]── 900 ms │ 期望（可选）     │
│              │           + 添加问题         │ [多行文字输入]   │
└──────────────┴──────────────────────────────┴──────────────────┘
```

- 图片与动画属于同一个 Review，可混合排列。选择图片时保留现有编辑体验。
- 文件导入与拖放可以接收视频，导入第一份素材时沿用自动创建 Review 的行为。
- 每次普通视频导入创建一个独立动画条目。只有通过条目内的“添加参考视频”入口，才建立对比关系。
- 首版使用已有录屏文件；App 内录屏入口另行规划。
- 初始不自动播放，显示首个可解码画面，音频默认静音。

## 3. 单视频审查

### 3.1 找到问题

提供播放/暂停、上一帧/下一帧、播放速度与时间轴拖动。速度选项为 0.25×、0.5×、1×；变速只影响预览，不改变素材和标注时间。

时间轴显示素材缩略图与问题标记。短时间段允许放大，便于检查几百毫秒的动画。逐帧依据实际视频帧时间，不假定固定帧率。

### 3.2 创建问题

画布顶部常驻「选择 V」和「框选标记 R」。点击框选时暂停播放并固定当前帧；拖动创建矩形后，已有选中问题时关联到该问题，否则创建新问题并聚焦描述。矩形带问题编号与四角手柄，选择模式支持移动、调整大小。右侧显示所属视频、标注帧时间及区域信息，并提供重新框选入口。双视频模式首版在当前实现一侧标记。

支持两个入口：

- 暂停后直接点击“添加问题”：绑定当前时间点。
- 拖出一段时间再点击“添加问题”：绑定选中时间段，可循环播放该段。

创建后自动聚焦问题描述。无需先框选，也无需先填写分类。用户可以稍后在暂停画面上补充矩形区域。

问题描述是完成一条反馈所需的唯一文字字段。空评论沿用现有行为，作为待填写问题保存；交接时显式标记待填写状态。

期望、组件名称和问题分类均为可选信息。分类放在展开的详情中，可选位移、缩放、透明度、速度与节奏、延迟、其他；分类不触发自动参数建议。

### 3.3 浏览与修改

- 点击问题列表项：暂停并定位到问题的时间点或时间段起点，同时高亮时间范围。
- 点击问题的区域缩略图：定位到实际画框的那一帧，显示矩形。
- “播放此段”从时间段起点开始循环。时间点问题仍可从该点正常播放，不虚构时间范围。
- 调整时间段时保持已有标注帧处于范围内；若要排除该帧，先明确移除或重建区域标注。
- 删除问题、调整时间与区域、编辑评论支持自动保存及撤销/重做。播放、拖动播放头不进入撤销历史。
- 播放期间隐藏可编辑矩形；暂停回到标注帧时恢复显示。首版不提供运动跟踪。

## 4. 参考视频对比

### 4.1 可选参考与并排布局

添加参考后，中间画布切换为左侧“参考”、右侧“当前实现”，标签始终可见。保留两份素材原始宽高比，不拉伸，也不把两侧像素差直接解释成设计偏差。

移除参考后仍可使用当前实现及其问题；操作支持撤销。首版所有问题时间与区域以当前实现为主，参考提供对照证据。

### 4.2 手动设置对齐起点

录屏经常包含不同长度的等待时间。因此第一次添加参考后，显示“设置对齐起点”：

1. 用户独立定位参考视频，点击“设为参考起点”。
2. 用户独立定位当前实现，点击“设为当前起点”。
3. 确认后使用同一个相对时间同步播放，两侧均保留原始时间读数。

对齐仅调整时间偏移，不拉伸时长。参考动画 400 ms、当前动画 250 ms 时，应能直接看出当前实现提前结束。

同步时间到达一侧文件末尾后，该侧保留最后画面并显示“视频已结束”；早于一侧文件开头时显示“此时间无画面”，不补造帧。首版不根据画面自动判断动画何时结束。

问题保存当前视频的原始时间与创建时的对齐信息。之后改变对齐起点，不改变问题发生的位置；旧问题保留原有参考对应关系，用户可通过显式“使用新的对齐方式”更新。

### 4.3 延后能力

叠加、像素差异图、自动起点检测和画面空间配准不进入首版。并排对比是首版唯一双视频模式。

## 5. Agent 交接

复用现有“复制交接提示词”、只读 MCP 和导出入口。用户在自己的项目会话中要求 Agent 读取反馈。

每条动画反馈应提供以下事实：

| 内容 | 用途 |
| --- | --- |
| Review、动画条目与问题 ID | 稳定定位反馈 |
| 用户原始描述与可选期望 | 表达修改要求 |
| 当前实现的视频标识及原始时间 | 确定问题所在素材与片段 |
| 对齐起点及对应参考时间 | 还原用户看到的比较关系 |
| 标注帧、区域与该帧尺寸 | 确定画面位置 |
| 原视频及带实际时间戳的关键帧 | 支持观察运动过程 |
| 待填写、参考缺失或抽帧失败状态 | 避免把不完整证据当成完整反馈 |

单帧不能证明速度或曲线问题。时间段交接提供覆盖起点、中间阶段和终点的帧序列，并允许继续按需读取。时间点问题返回该点画面及视频上下文，不能声称已覆盖整个动画。

用户没有填写的参数保持未知。视频中的像素位移不自动转换成 Flutter 逻辑像素或 iOS 点；评论中的建议不变成工具测得的事实。

### 5.1 MCP 能力草案

保留现有五个工具及截图行为。新增能力暂拟如下，具体接口需在实现前检查现有协议代码与兼容性：

- 获取动画条目：返回视频元数据、问题和对齐关系。
- 获取指定帧：返回原始或标注图片，包含请求时间与实际解码帧时间。
- 获取片段帧序列：按问题范围和数量上限返回，包含实际时间戳与省略说明。

帧读取设定数量、分辨率与响应大小上限，避免一次读取完整长视频。App 退出后仍应能通过 MCP 获取已保存的动画反馈。

### 5.2 文件导出

延续单次导出完整文件夹、不覆盖已有目录的行为，新增 videos 与 frames 资产。Markdown 与 JSON 引用包内相对路径，包含原始视频、标注帧和有限关键帧。

导出默认复制整份原视频，并在执行前显示预计大小和“包含完整录屏”的说明。只导出片段的裁剪能力后续再设计；首版不让用户误以为标注范围等于导出范围。

不生成未经用户提供或测量支持的修改参数。相同问题通过 MCP 与文件导出应能还原同一组事实。

## 6. 数据与兼容边界

概念上，一个 Review 可以包含截图条目和动画条目；动画条目关联当前视频、可选参考视频与问题。具体存储结构另行设计，不在本阶段要求整体重构。

- 图片沿用现有像素与归一化坐标语义。
- 视频区域基于应用旋转方向后的可见帧，记录该帧尺寸、原始时间和归一化区域。
- 内部时间保留媒体时间精度，界面以毫秒展示，不以显示时四舍五入的数值反推实际帧。
- 原视频作为不可变本地资产保存；缩略图与关键帧作为可重建派生资源。
- 旧截图 Review 应完整读取；新增字段或版本升级必须有明确兼容策略，旧数据读取失败时仍停止写入。
- 移除素材后保留资产以支持撤销，沿用现有不自动清理资产的策略。
- 不支持的视频、复制失败、空间不足或解码失败都应给出明确状态，不留下假成功条目，不影响已有 Review。

## 7. 首版范围与验收场景

首版包括文件视频导入、单视频播放与逐帧、时间点/时间段问题、可选单帧矩形、可选参考并排与手动对齐、自动保存和撤销、MCP 读取与完整导出。

不包括 App 内录屏、视频剪辑、运动跟踪、自动识别曲线、自动生成问题、代码定位及代码修改。

验收围绕完整工作流：

1. 只有当前录屏时，不框选也能保存“关闭突然跳走”的时间段反馈，并交给 Agent。
2. 两段视频分别从第 2 秒和第 5 秒开始动画时，手动对齐后可比较同一相对时刻，同时保留真实速度差异。
3. 不同帧率或可变帧率视频逐帧浏览与导出后，返回帧的实际时间可追溯。
4. 组件在选段中发生移动时，单帧矩形不会被展示为已跟踪整个过程。
5. 重启后恢复视频、时间范围、评论和参考关系；App 退出后 MCP 仍能读取。
6. 复制导出包到其他目录后，文档仍能找到视频与帧图片。
7. 旧截图 Review、截图 MCP 读取及截图导出保持可用。
8. 无参考、素材损坏、抽帧失败或视频提前结束时，界面与交接内容均明确显示状态。
